# US-027 — Guide du contributeur : comment concevoir une bonne carte

- **Epic** : EPIC-08
- **Statut** : À affiner
- **Priorité** : Should
- **Taille** : S
- **Branche** : `us-027-guide-contributeur`

## Récit

En tant que **tech lead ou architecte**, je veux **un guide clair pour concevoir une carte** afin de **proposer une
carte juste, jouable et pédagogique sans connaître le code du jeu**.

## Critères d'acceptation

- [ ] Un guide (`docs/produit/guide-contributeur.md`, et une page du jeu qui le reprend) explique en une page :
      familles, types de carte, raretés, statistiques (Débit, Attaque, PV) et capacités existantes, avec leurs
      ordres de grandeur par rareté.
- [ ] Il donne un **gabarit** de proposition : nom, famille, type, rareté visée, statistiques suggérées,
      capacités, effet éventuel, texte « En vrai » (3 lignes au plus), sources, et le nom de l'auteur.
- [ ] Il fixe les **règles de contenu** : rien de confidentiel (serveurs, adresses, clients, failles non
      corrigées), pas de marque dénigrée, un ton bienveillant, un texte compréhensible par un non-spécialiste.
- [ ] Il montre **deux exemples commentés** tirés du set 1 (une bonne carte, et une carte retravaillée).
- [ ] Il explique ce que devient une proposition : relecture, équilibrage, publication et crédit.
